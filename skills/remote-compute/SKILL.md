# remote-compute

复制到本人目录使用（如 `~/.claude/skills/remote-compute/`，或用仓库的 `skills/install.sh`）。模板中不写密码、令牌或私钥。

## 连接信息

每个项目在仓库根目录的 `CLAUDE.local.md`（不提交，加入 `.git/info/exclude`）中记录：

```text
host: compute-node-1          # ~/.ssh/config 中的别名
dir: /data/<user>/<project>   # 远程工作目录
env: source ~/venvs/<project>/bin/activate   # 远程环境激活命令
scheduler: slurm | systemd-run | tmux
```

缺少任何一项时先问用户，不要退回工作站执行重计算。

## 1. 远程提交

1. `git status` 确认本地已提交；`git push`。
2. `ssh <host> 'cd <dir> && git status --short && git fetch && git checkout <commit>'`；远程有未提交修改时先告诉用户。
3. 按 scheduler 提交，命令中写明资源参数，日志写到 `<dir>/logs/<job-id>.log`，日志首行记录 commit。
4. 返回：任务 ID、commit、日志路径、产物目录。

预计超过几分钟的任务一律后台提交，提交后不要在前台等待；任务不能依赖手机或 SSH 前台连接。

## 2. 状态查询

输入任务 ID，返回调度状态、关键指标的最新值（step、loss 等）、日志末尾 20 行和产物目录列表。回答要短到能在手机上一屏看完。停止任务（`scancel`、`kill` 等）前必须先征得用户同意；Paseo 中停止代理不代表远程作业已结束。

## 3. 结果同步

- 先在远程聚合或抽样，只拉指标、日志片段、少量样例和图片。
- 拉取前用 `du -sh` 查看大小；超过 50 MB 先告诉用户。
- 存到 `~/results/<project>/<job-id>/`，并记录远程路径与时间。
- 不拉数据集、权重、检查点和大批量结果；rsync 默认不加 `--delete`。

## 4. 结果回传到手机

工作站常开，手机通过 Paseo 打开的就是工作站上的会话，所以“手机上看结果”只需要把结果整理在工作站上：

1. 同步完成后在 `~/results/<project>/<job-id>/` 写 `summary.md`：任务 ID、commit、状态与用时、关键指标表（与上一版对比时列出差值）、图片相对链接（如 `![loss]` 指向同目录的 `loss.png`）、远程完整产物路径。
2. 曲线图在节点上生成 PNG 后再拉回，宽度不超过 1200 px，便于手机查看。
3. 在会话里直接回复摘要：3–5 行结论 + 指标表 + `summary.md` 路径。用户在手机上可以接着发下一条指令（例如“和上一版对比”“改学习率重跑”）。
4. 用户要求“跑完通知我”时，提交时在节点任务末尾写完成标记文件；之后的查询以标记文件为准，不要轮询占用前台。

## 5. 可视化连接

节点上的网页服务（TensorBoard 等）通过两段 SSH 隧道给本人电脑查看，端口按人或任务错开：

```bash
# 工作站
ssh -N -L 127.0.0.1:<工作站端口>:127.0.0.1:<服务端口> <host>
# 本人电脑
ssh -p 2222 -N -L 127.0.0.1:<本地端口>:127.0.0.1:<工作站端口> <user>@<WS_IP>
```

返回可访问地址 `http://127.0.0.1:<本地端口>` 以及关闭方式。手机上优先看第 4 节的摘要与图片。

## 规则

- 远程数据、权重和检查点不删除、不覆盖。
- 只使用本人 SSH 身份；连接失败或需要密码时停下来告诉用户。
- 大改前先提交或打快照；已推送的历史用 `git revert` 回退。
